## 고친 것 (커리큘럼 v2.8)

영역 담당 4명이 47개를 고쳤다. 검증 담당이 영역마다 다시 확인하고 보정했다.

**과정 전체**
- **PR 의식 덜기: 문서는 main에 바로, GIF·셀프 리뷰 코멘트는 주 1개 PR** — META.prTypes(구현·Git·선택)를 넣었다. summary.js(c4-X-summary.js)와 페이지 items()가 문서 과제만 있는 날에는 PR을 붙이지 않는다(요일별 PR 88일 → 73일). 6장 규칙 한 줄·표·첫 PR 따라 하기·이슈 정리, 2장 리듬 토요일, 5장 작업 흐름은 '문서는 PR 없이 main에, 초안을 먼저 커밋'으로 맞췄다. 문서만 올리는 날의 기록 ① 카드는 브랜치 대신 main 순서(steps.docUp)를 보여 준다. GIF와 셀프 리뷰 코멘트는 한 주에 PR 1개(동작이 가장 잘 보이는 PR)로 줄였다(steps.prOpen·prMerge, PR 본문 GIF 칸, issueBlock도 같이).
- **핵심 경로의 deferred를 둘로 나눈다: 라이브 실기 후보만 만들고 나머지 [필수]는 필기만 대비** — 1장 수료 평가 표의 라이브 실기 칸에 후보 6개를 적었다(7장 수료 대비 주 수요일 목록과 같다). 2장 핵심 경로는 미룬 것을 둘로 나눈다. ⓐ 라이브 실기 후보이거나 다음 주가 쓰는 것은 토요일 보충 칸에서 만든다. ⓑ 나머지 [필수]는 만들지 않고 그 주차 자가 점검 질문에 ↺를 눌러 회상 카드·관문 점검에 먼저 나오게 한다. 2장 ⑤, 7장 「미뤄도 되는 것」, 수료 대비 주 메우기도 같은 기준으로 고쳤다. 만들 양이 줄어서 시간은 줄기만 한다(B·D·H).

CLAUDE.md 주간 점검은 3줄 가운데 1줄을 PR의 「AI 없이 내가 먼저 쓴 커밋」에서 고른다. 설명하지 못하면 다음 주 그 종류의 과제는 한 단계 아래로 하고, 새 4단계에서 레벨을 정한다. 페이지의 주간 점검 명령(codeCheckBlock)에 빌드 줄 칸과 안내를 붙였다. 기존 10분 점검 안에서 한다.
- **관문 채점 10문항 구성: 단계 질문 7 + 지난 단계 C++ 기본 2 + 처음 보는 코드 읽기 1** — 7장 관문 운영 ①과 CLAUDE.md의 관문 채점·수료 모의 채점을 같은 10문항 구성으로 정했다. 그 단계 질문 7개(마지막 주 질문은 2개까지), 지난 단계 C++ 기본 2개, 처음 보는 코드 읽기 1개다. 코드 읽기는 과외 세션이 5대 실수 하나를 심은 5~10줄 코드를 새로 쓰고 학생이 문제 줄을 찾는다.
