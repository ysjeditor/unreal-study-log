고친 문항은 문제 유형별로 다음과 같습니다.

1. 기술 오류

   - P1-006 B: GitHub은 100MB가 넘는 파일을 LFS 없이 받지 않으므로, 200MB 레벨 파일로는 'LFS 없이 운영' 상황이 성립하지 않습니다. 60MB로 바꿨습니다.
   - P1-017 B: 모범 답안이 bool의 b 접두사까지 UHT 빌드 에러처럼 써 있었습니다. b는 코딩 표준일 뿐 빌드 에러는 나지 않는다고 바로잡았습니다.
2. 커리큘럼 근거 부족
   - P1-044 A·B: 'bCanEverTick이 true여야 SetActorTickEnabled로 켤 수 있다'를 정답으로 요구했습니다. 그런데 커리큘럼에는 '기본은 bCanEverTick=false, 필요할 때만 SetActorTickEnabled'로만 나옵니다. 이 사실을 문제에 참고로 넣었습니다.
   - P1-047 B: Hold 트리거는 W04 심화(선택) 내용입니다. 그래서 이름을 몰라도 '일정 시간 눌러야 발동하는 Trigger'라고 쓰면 정답으로 하도록 채점표를 고쳤습니다.
3. 전제·채점 모호
   - P1-042 A·B: 레벨에 놓은 것이 C++ 클래스인지 BP 자식인지 불분명했습니다. C++ 클래스를 놓으면 BP 로그는 찍히지 않습니다. BP 자식을 놓았다고 명시했습니다.

   - P1-034 B: ②⑤는 A·B 어느 쪽에 둬도 동작해서 정답이 둘이었습니다. '워커 스레드에서 해도 안전한 일은 B로' 원칙을 문제에 넣어 정답을 하나로 만들었습니다.
   - P1-052 A: 람다를 다이나믹 델리게이트에 붙이게 하면서, 정답만 문제에 없는 두 번째 델리게이트를 전제했습니다. 이 점을 문제에 명시했습니다.

## 코딩테스트 (24문항 · 고침 3)

24문항(48개 형)을 모두 확인했다. 이 PC에는 Windows SDK가 없어 C++ 컴파일러를 쓸 수 없었다. 그래서 각 형을 Node.js 참조 구현으로 따로 짜서 예제와 채점 테스트(생성 규칙 테스트 포함)의 기대 출력을 전부 다시 계산했다. 결과는 모두 일치했다. 작성자가 적은 오답 함정 값도 주장대로 나왔다(float, 배낭 갱신 방향, k를 안쪽에 둔 플로이드, 연쇄 회전 즉시 적용, % 양수화 등). 채점표 합계는 전 문항 10점이고, 문제 문장은 모두 창작이며 커리큘럼 밖 API는 없었다.

고친 문항은 3개다.
